# UNIT-05 マスタメンテナンス - Functional Design 計画

## ユニットスコープ（前提確認）

対応要件: FR-4.1〜FR-4.8（テーブル/ビュー一覧、レコード一覧、絞込・SQL入力検索、レコード編集・一括反映、レコード作成・削除）
対応コンポーネント: COMP-13 MasterDataService
対応ストーリー: STORY-4.1, STORY-4.2, STORY-4.3, STORY-4.4
前提ユニット: UNIT-01〜UNIT-04（実効権限判定=`EffectivePermissionResolver`、スキーマ情報=`SchemaIntrospectionService`に依存）

既存の決定事項（requirements.md §5.2/§5.4、UNIT-04実装済み）:
- 主権限は3値（`NONE`/`READ`/`UPDATE`）、階層はカラム＞テーブル＞スキーマ（FR-2.4、`EffectivePermissionResolver.resolvePrimary`）
- レコード作成可否: `CREATE`補助権限があり、かつ（主キーなし、または全主キー列が`UPDATE`以上）（FR-2.6、`canCreate`）
- レコード削除可否: `DELETE`補助権限があり、かつ主キーを持ち、かつ全主キー列が`READ`以上（FR-2.7、`canDelete`）。主キーなしテーブルは常に削除不可
- 実効権限判定はUNIT-04時点でAPI非公開（Java直接呼び出しのみ）。本ユニットのバックエンドから同一プロセス内で直接利用する
- スキーマ情報はUNIT-03の`SchemaIntrospectionService`が保持（`SchemaSnapshot`/`SchemaTable`/`SchemaColumn`、`TableType.TABLE`/`VIEW`区別あり）
- 対応RDBMS: MySQL / MariaDB / PostgreSQL / H2（複数方言、`RdbmsDialectStrategy`既存）
